Original: «Se ofrecen preferencias de ticket que la plantilla fija ignora.» Aceptación: «Cada opción visible produce un efecto documentado o deja de presentarse como aplicable.»

Confirmado: receiptRows usa la plantilla fija aprobada; no consume pie libre ni opciones contacto/serie/vendedor, tampoco descripción comercial/correo de empresa. La configuración prometía que todos esos cambios afectarían próximos tickets.

Se retiran esos seis controles de la pantalla, conservando sus valores/contrato API y columnas para compatibilidad, sin borrarlos ni imponer nuevos valores a históricos. Se mantienen nombre comercial (usado por expediente A4, con aclaración), dirección/ciudad/teléfono (cabecera térmica), formato predeterminado 58/80 y márgenes internos efectivos. La confirmación especifica qué se aplica al ticket; se explica contenido fijo. No se modifica receiptRows, PDF, ancho físico, cláusulas aprobadas ni datos reales. Correo/descripción y preferencias heredadas no son presentados como opciones aplicables.

Pruebas: 12/12 unitarias de tickets, incluida regresión nueva que contrasta opciones heredadas ignoradas con campos/márgenes efectivos. Son casos únicos, no seis pruebas nuevas. La revisión de fotos en ese test UI usa respuestas interceptadas sintéticas; el backend/storage/RBAC real aislado se prueba en AUD-08.
