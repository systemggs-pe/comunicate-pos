# AUD-07 — RESUELTO LOCAL

Original: «El datamodel no describe completamente el estado producido por las migraciones.» Aceptación: «Historia desde base vacía y definición reconciliadas, excepciones intencionales justificadas.»

Se reprodujo diff exit 2 después de aplicar las 19 migraciones desde una base vacía nueva en PostgreSQL 55438. La causa es representación incompleta en Prisma: UUID generado por PostgreSQL en ClientDocument, defaults SQL de updatedAt en CompanySettings/ClientDocument, seis FK con ON UPDATE NO ACTION implícito en SQL y el único operationId/phone. Se representan esos valores en schema.prisma; no se aplica el SQL destructivo del diff ni se cambia ninguna migración.

Resultado: migrate diff --from-schema-datasource --to-schema-datamodel --exit-code --script devuelve 0, «empty migration»; prisma validate PASS. Dos pruebas de contrato SQL pasan y verifican defaults, acciones FK, único, restricciones documentales/completado y secuencias. El primer migrate deploy se intentó inmediatamente tras iniciar el contenedor y falló con schema-engine genérico; tras confirmar pg_isready, las 19 migraciones se aplicaron correctamente. Se conserva el log, no se declara corrupción ni se atribuye una causa exacta no emitida por el motor.

## SQL intencional fuera de Prisma

Los CHECK de formato/slots/dinero/completado/tamaños/categorías, triggers de consistencia/inmutabilidad/ámbito/última referencia, índices parciales, funciones y secuencias visibles pertenecen al historial SQL y no están totalmente representables en Prisma. Un diff vacío compara la parte representable, no acredita que no existan estas garantías. Deben conservarse y revisarse al generar cualquier migración futura; nunca aplicar un diff ciego ni db push sobre comerciales. Las pruebas migration-contract y las suites de integridad ejercen una selección crítica; no sustituyen revisión de cada migración productiva.

margin58 continúa mapeada a columna margin48 por compatibilidad; el papel sigue midiendo 58/80 mm. No se añade migración porque el estado deseado ya existe en SQL. No se modificó el esquema comercial ni se ejecutó Prisma generate sobre la DLL del POS en uso. La generación/build se comprueban en copia aislada de compilación al cierre.

Archivos: prisma/schema.prisma; tests/integration/migration-contract.test.ts. Evidencia: migrations/migrations-ready, aud07-before, aud07-diff-final, aud07-validate y aud07-contract en evidence/.
