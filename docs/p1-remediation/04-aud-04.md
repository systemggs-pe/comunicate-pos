# AUD-04 — Recuperación real en recursos aislados

La causa era el puerto local 55432 y el servicio Compose postgres fijados en el transporte. El entorno de auditoría no podía seleccionar su instancia aislada.

Se añade un perfil explícito con RECOVERY_POSTGRES_CONTAINER y RECOVERY_POSTGRES_PORT. Ambos son obligatorios juntos; se validan puerto, nombre de contenedor, protocolo PostgreSQL, loopback y nombres de base sintéticos. Un perfil alternativo rechaza communicate_pos. La restauración sigue exigiendo nombre restore, confirmación exacta, base inexistente y bucket nuevo. Sin perfil se conserva el transporte local existente. Los argumentos se pasan directamente a docker exec, sin shell.

El fixture de recuperación usa IMEI sintéticos válidos y ambas caras de DNI para cada operación, sin exenciones a AUD-02. La prueba conserva las comprobaciones de dinero, secuencias, privacidad, autorización, sesiones, archivos compartidos, checksum y no sobrescritura.

Evidencia: evidence/recovery-current.json y .log: 2/2 PASS mediante createBackup/restoreBackup reales; PostgreSQL 55435 y MinIO 59020 aislados. Recuperación: 1000 clientes sintéticos, 20 ventas, 80 IMEI, importe 2005.00; 40 fotografías compartidas en 80 vínculos. También se comprueba rechazo de fotografías ausentes o corruptas.

No se restauró sobre PostgreSQL comercial ni sobre el MinIO habitual. No se ejecutó transporte cloud. AUD-05 continúa independiente y externo.
